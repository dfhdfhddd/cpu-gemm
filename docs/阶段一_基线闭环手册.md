# 阶段一：朴素 GEMM 基线闭环手册

## 1. 阶段目标

建立一个以后所有优化都能依赖的公平 baseline。阶段结束时必须能够从源码完成：

```text
配置 -> Release 编译 -> 正确性测试 -> benchmark -> CSV -> Git 冻结
```

最终结果应满足：代码正确、输入可复现、计时稳定、结果可复查，并且后续优化不会修改 `gemm_ijk` 的行为。

## 2. 每一步要做什么

### 第 1 步：建立工程骨架

创建 `include`、`src`、`tests`、`results` 和 `docs`，准备 `CMakeLists.txt`、`README.md` 与 `.gitignore`，初始化 Git。

**结果要求：** CMake 能配置并生成构建目录，构建入口固定，临时构建文件不会被提交。

### 第 2 步：固定 GEMM 接口

统一约定输入为连续 `N x N` row-major `float` 数组，调用者负责分配 `A/B/C`，GEMM 函数只写入 `C`。

**结果要求：** 后续替换实现时，只替换函数，不改测试和 benchmark 的调用方式。

### 第 3 步：实现朴素 `ijk`

只实现数学公式：外层遍历行 `i`，中层遍历列 `j`，内层遍历累加维度 `k`。这一阶段不加入分块、SIMD、OpenMP、转置或手工预取。

**结果要求：** `src/gemm_ijk.cpp` 是清晰、无额外优化技巧的参照实现。

### 第 4 步：准备固定输入

使用固定随机种子（当前为 `12345`）生成 `[-1, 1]` 的随机矩阵。随机数生成、内存分配和初始化必须在计时区间外完成。

**结果要求：** 同一规模重复运行时，输入和 checksum 可复现。

### 第 5 步：建立正确性测试

依次覆盖标量、全 1、单位矩阵、手算小矩阵、固定随机矩阵，并与独立参考结果逐元素比较。使用绝对误差或相对误差阈值，不使用浮点完全相等判断。

**结果要求：** 错误时打印失败位置和误差，并返回非零退出码；不能只看程序是否崩溃。

### 第 6 步：建立最小运行链路

主程序控制测试规模，完成分配、填充、调用 GEMM、checksum 和结果输出。不要打印大矩阵，也不要在主程序中复制 GEMM 逻辑。

**结果要求：** 程序能稳定输出规模和 checksum，且只调用项目实际编译出的 `gemm_ijk`。

### 第 7 步：统一 benchmark 流程

将随机数生成、预热、清零、重复调用、计时和统计集中到 benchmark 流程中。先预热 3 次，再正式运行 20 次。每次正式运行前重置 `C`，计时只包住一次 GEMM 调用。

**结果要求：** 输出中位数、最小值、平均值、标准差和每个规模的耗时；重复运行没有明显异常漂移。

### 第 8 步：计算 GFLOPS

按 `2 x N^3` 计算浮点操作数，并使用秒为单位的中位数耗时计算 GFLOPS。

**结果要求：** 每个矩阵规模都有可比较的 GFLOPS，不能只报告“运行了多少毫秒”。

### 第 9 步：写出 CSV

benchmark 自动覆盖写入 `results/benchmark_results.csv`。CSV 至少保留实现名称、规模、主要耗时指标、GFLOPS 和 checksum。

**结果要求：** 一次 benchmark 即可生成完整原始结果，不需要手工抄写终端输出。

### 第 10 步：运行最终规模

当前基线规模为 `64、128、256、512、1024`。确认 CSV 中没有旧的 `N=4` 或 `N=16` 记录。

**结果要求：** 每个最终规模都有正确性结果、耗时、GFLOPS 和 checksum，且大规模运行没有越界或崩溃。

### 第 11 步：记录实验环境

在 README 和实验记录中写明 CPU、内存、编译器版本、CMake 版本、Release 参数、电源模式、测试日期、预热次数和正式次数。

**结果要求：** 其他人能根据文档判断这些数据是在什么条件下得到的。

### 第 12 步：冻结 baseline

从本机重新完成 Release 编译、CTest 和 benchmark，核对 CSV、README、源代码和提交内容。确认无误后提交 Git，并可创建 `baseline-v1` 标签。

**结果要求：** 之后只新增 `gemm_ikj`、`gemm_kij` 等实现，不修改 `gemm_ijk` 和已冻结结果。

## 3. 当前项目的执行命令

在仓库根目录执行：

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\test_gemm.exe
.\build\Release\benchmark_gemm.exe
```

性能数据只采用 Release 运行结果。测试时插电，关闭会持续占用 CPU 的无关任务，并记录电源模式；不要在同一批实验中切换测试条件。

## 4. 阶段一验收清单

- [x] `ijk` 只表达朴素三重循环；
- [x] 固定随机种子和固定输入范围；
- [x] 有确定性案例和随机案例；
- [x] 有逐元素误差检查；
- [x] 计时不包含分配、随机数、预热和 checksum；
- [x] 3 次预热、20 次正式计时；
- [x] 输出中位数、最小值、平均值、标准差、GFLOPS 和 checksum；
- [x] 自动生成 CSV；
- [x] 最终规模为 `64、128、256、512、1024`；
- [ ] 用最终本机 Release 结果确认 CSV 与文档完全一致；
- [ ] 提交并冻结 `baseline-v1`。

只有最后两项也完成，阶段一才算正式结束。

## 5. 不属于本阶段的内容

循环换序、分块、AVX2、OpenMP、线程调优和成熟库对照都不要提前混入 baseline。它们会改变参照物，必须在阶段一冻结后进入下一阶段。
