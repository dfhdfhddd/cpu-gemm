# 阶段三：矩形分块参数化与候选配置比较说明

## 1. 本次实现的目标

前一轮已经完成 `Mc、Nc、Kc` 都取 `32、64、128` 时的 27 组探索。本轮根据两次完整 benchmark 的结果，缩小范围，只比较当前最有代表性的六组候选参数，而不是每次运行都重复测试全部 27 组。

上一轮的组合数量为：

```text
3 × 3 × 3 = 27 组
```

本轮固定比较以下六组：

```text
Mc=32,  Nc=128, Kc=128
Mc=64,  Nc=64,  Kc=64
Mc=64,  Nc=128, Kc=128
Mc=128, Nc=64,  Kc=128
Mc=128, Nc=128, Kc=64
Mc=128, Nc=128, Kc=128
```

六组配置覆盖了当前数据中 `N=256、512、1024` 的代表性优胜者、综合均衡者和稳定对照组。

## 2. 参数化函数

真正执行计算的函数现在是：

```text
gemm_blocked_4x4_impl(A, B, C, N, Mc, Nc, Kc)
```

三个参数含义：

- `Mc`：矩阵 C 的行块高度，同时对应 A 的行块高度；
- `Nc`：矩阵 C 的列块宽度，同时对应 B 的列块宽度；
- `Kc`：归约维度块大小，同时对应 A 的列块宽度和 B 的行块高度。

内部循环分别使用：

```text
i    += Mc
col  += Nc
red  += Kc
```

4×4 微内核仍然负责完整的主体区域，边缘区域使用标量循环处理。

## 3. 自动生成算法名

历史上的全组合版本使用三层循环：

```text
for Mc in {32, 64, 128}
  for Nc in {32, 64, 128}
    for Kc in {32, 64, 128}
```

算法名由参数自动拼接，例如：

```text
gemm_blocked_Mc32_Nc64_Kc128_4x4
```

名称中明确写出三个方向的块大小，便于在 CSV 中筛选和比较。

当前版本改为保存一个 `BlockConfig` 配置表，并逐项遍历：

```text
for config in block_configs
    run_benchmark_blocked(..., config.Mc, config.Nc, config.Kc)
```

因此新增或删除候选配置只需要修改配置表，不需要复制函数，也不需要手写算法名。

## 4. 参数化测速入口

普通 GEMM 使用：

```text
run_benchmark(gemm_func, N, num_iters)
```

参数化分块 GEMM 使用：

```text
run_benchmark_blocked(gemm_blocked_4x4_impl, N, num_iters, Mc, Nc, Kc)
```

两者在 `benchmark_utils.cpp` 中共用同一个计时统计流程，因此都使用：

- 固定种子的随机矩阵；
- 3 次预热；
- 20 次正式计时；
- 中位数、最小值、平均值、标准差；
- GFLOPS 和 checksum。

区别只有计算函数调用时是否需要额外传入 `Mc、Nc、Kc`。

## 5. 如何运行和分析

每个 `N` 现在输出 6 行结果。重点查看 `N=256、512、1024`，按 `GFLOPS` 从高到低排序，记录六组配置的排名和运行间波动。

不要只保留最快的一组。应保留完整 CSV，并在重复测试中确认前几名是否稳定。

建议对这六组配置使用相同输入、相同编译条件，连续进行 3～5 次独立运行，再决定阶段三的代表性矩形分块配置。不要只依据某一次运行的最高 GFLOPS；应同时查看中位数、标准差和 checksum。

- `src/block_size/gemm_blocked_4x4.cpp`：将分块实现参数化为 `Mc/Nc/Kc`，继续复用 4×4 微内核；

- `include/benchmark_utils.h`：增加参数化测速函数和函数指针类型；
- `src/benchmark_utils.cpp`：抽取公共测速统计流程；
- `src/main.cpp`：遍历六组候选参数并自动生成算法名；
